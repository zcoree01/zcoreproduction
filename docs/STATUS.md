## Not done yet / known gaps

- Forgotten passwords: only the administrator resets them (no e-mail / SMS). Temporary passwords have little entropy by design (easy to read out); they work until the first sign-in, which must replace them, and sign-in is rate limited by Supabase Auth.
- Users can be created and their passwords reset, but not yet edited, deactivated or re-roled in the UI (RLS already allows `users.manage` to update memberships).
- No custom-role management UI; no org settings screen.
- After login the user always lands on the role home (no "return to requested page").
- Dev overlay shows an informational `instant` validation message when an operator opens `/dashboard` (intentional redirect to `/floor`).
- Table sorting is fixed (by username); column sorting UI not yet added to DataTable.
- Demo org contains an extra user `testniradnik` (Direktor) created by hand via the UI on 2026-10-23 (audit log: `users.create` by `admin`). Tests do not depend on the exact user count.
- DB/e2e tests run against the real linked project (no Docker, no separate test project); test tenants also appear in its tables.
- Not deployed yet: Vercel project not connected (CLAUDE.md: auto-deploy from `main`, preview per PR).
- E2E tests run serially (`workers: 1`, ~2.5 min), because a sign-in revokes the same user's sessions in parallel tests.
- Machines/employees: no detail page, history view, attachments, serial number or shift data yet; machine status is manual (production reports in Phase 3 will drive running/stopped). Module activation (`org_modules`) is checked in pages for UX only; data access is governed by permissions/RLS.
- Self-registered organizations get every module as a trial (14 days by default); after it ends the platform admin switches modules on (no billing). Organizations created by scripts still use `ensureModuleEnabled()`.
- Registration: no CAPTCHA (rate limit per hashed client address + honeypot) and no e-mail verification; claims of existing directory entries wait for the platform admin. Directory entries are never deleted; bank accounts can be changed only by the owner. In local dev "Uđi u firmu" replaces the platform admin's own session in that browser (one host). Typing into a form before a page is hydrated in dev mode is lost once (e2e waits for network idle).
- Supabase Auth: enable leaked-password protection in the dashboard (advisor warning). Advisor warnings for `write_audit`, `get_login_organization`, `set_machine_status` and `product_history` (SECURITY DEFINER, enforce their own rules) are intentional.
- Attendance (part A): no schedule screens, rotation, absences, corrections, holidays, payroll calculation, exports or kiosk yet (parts B / C); without a schedule every clock-in is matched to the nearest shift of the organization (two shifts with the same start are ambiguous until the schedule exists); the rounding step is prepared but not configurable yet; alerts are only in the app (bell polled every 30 s). Starting work clocks a worker in on test tenants too, so test cleanups delete `attendance_alerts` / `attendance_sessions` before employees.
- Production reporting: no attachments on reports; no shift filter on the overview and no shift on reports / downtime yet (after attendance part C); tools are free text (no tool store); reports can be voided but not edited; a first non-cutting operation cannot report more than ordered (spares only via cutting); pieces left unreported at finish simply stop (no automatic scrap); a worker may have sessions on several operations at once; close-request notifications only in the app (bell, polled every 30 s; no push / e-mail). No finished-goods inventory yet. Directory views call private functions granted to `authenticated` only (service-role scripts read base tables). No order-specific uploads (drawings come from the product revision). Priority/slack uses `work_hours_per_day` until shifts exist; no calendar (weekends count). ISO week + calendar year in numbers: on 1–3 January the week can be 53 of the previous year. Warnings are shown in lists and screens, there are no notifications yet. No reorder of operations on an order; no partial quantities/splitting. Machine overlap only considers released orders.
- Products: operators see product data only through their orders on the floor; materials are not linked to the material warehouse yet; no BOM/assemblies; no weight for profiles (shape "other"); product types are a catalog, units a fixed list. "Current operation" and production status per product/customer come with production orders. Attachments: only PDF/images (no DXF/STEP/NC programs); files are never deleted from Storage. History shows changed field names, not old/new values. Starter densities are typical data-sheet values (each organization can correct them). The old catalog kind `material_shape` is no longer offered (rows stay in the database).
